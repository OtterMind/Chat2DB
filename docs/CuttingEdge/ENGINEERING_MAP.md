>
> **قانون این سند:** هر عددی که اینجا آمده *اندازه‌گیری* شده، نه تخمین. جلوی هر ادعا،

## ۰) یک‌خطی: این برنامه چیست؟

**Cutting Edge** یک تدوین‌گر رومیزیِ هوشمند برای ویدیوی فرم کوتاه است: فوتیج خامِ کاربر
(والیبال، بدنسازی، طناب‌زنی، ولاگ) را می‌گیرد، لحظه‌های قوی را با *سیگنالِ اندازه‌گیری‌شده*
پیدا می‌کند، یک تدوین عمودی با زیرنویسِ هم‌زمانِ کلمه‌به‌کلمه، موسیقیِ duck‌شده و رنگِ
هم‌خوان با یک ویدیوی الگو می‌سازد، و خروجی MP4 می‌دهد — همه‌چیز **روی دستگاه خود کاربر**،
بدون آپلود. رابط، یک سیستم طراحی Hybrid است که اساتید تعیین کردند و مو‌به‌مو اجرا شده است.

## ۱) پشته‌ی فناوری (همه‌چیز محلی)

| لایه | فناوری | چرا این |
|---|---|---|
| پوسته‌ی دسکتاپ | Electron 31 | یک کدبیس برای ویندوز؛ آپدیت افزایشی با `electron-updater` + blockmap |
| رابط | React 18 + Vite 5 + TypeScript | کامپوننت‌محور؛ `tsc --noEmit` بخشی از CI است |
| وضعیت ادیتور | Zustand | سلکتورهای دقیق تا تیک playhead کل صفحه را رندر نکند |
| بک‌اند | FastAPI + Uvicorn روی `:8742` | یک پروسس؛ WebSocket برای پیشرفت کارها |
| ذخیره‌سازی | SQLite (thread-local) | بدون سرور خارجی؛ پروژه‌ها `.ceproj` چند کیلوبایتی |
| موتور رندر | FFmpeg (یک `filter_complex`) | NVENC اگر کارت هست، وگرنه libx264 |
| بینش | faster-whisper / silero-VAD / MediaPipe / Ollama | **همه اختیاری و on-demand**؛ بدون آن‌ها هم برنامه کار می‌کند |
| زبان پایتون | 3.11 | پین‌شده در CI |

**حجم‌ها (اندازه‌گیری‌شده):** بک‌اند ≈ 15,600 خط پایتون در 96 فایل · رابط ≈ 12,100 خط
TS/TSX · 37 ماژول موتور · 8 ماژول مغز · 27 روتر با **118 endpoint** · 55 فایل تست بک‌اند.

## ۲) نقشه‌ی معماری

```
┌────────────────────────────  Electron (main)  ────────────────────────────┐
│  updater.ts (آپدیت افزایشی) · preload.ts (پل امن) · main.ts (پنجره/منو)      │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ IPC
┌───────────────────────────────▼───────────────────────────────────────────┐
│  Renderer — React/Vite                                                    │
│  Home(لانچر) · StyleMatch · Studio(ادیتور) · Settings · Doctor · …          │
│  editor/: Timeline · PreviewMonitor · MediaBin · Scoreboard · Toolbar      │
│  api/: کلاینت axios با interceptor (خطای خوانا + correlation-id)            │
└───────────────────────────────┬───────────────────────────────────────────┘
                    HTTP /api (118 endpoint) · WS /ws
┌───────────────────────────────▼───────────────────────────────────────────┐
│  Backend — FastAPI :8742                                                  │
│  routers/ (27): media·render·captions·style·brain·multicam·emotion·…       │
│  core/engine/ (37): compose·style·transcribe·reframe·subtitles·emotion·…  │
│  core/brain/ (8): objective·planners·race·editor_brain·meaning·intake      │
│  core/providers/: کانال افزونه‌ی برون‌فرآیندی                               │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ subprocess
┌───────────────────────────────▼───────────────────────────────────────────┐
│  FFmpeg (رندر/پیش‌نمایش/آنالیز) · افزونه‌ها (هرکدام پروسس خودشان)            │
└───────────────────────────────────────────────────────────────────────────┘
```

**جریان یک تدوین خودکار:** ingest → proxy → analyze (سکوت/صحنه/ضرب) → transcribe
(گفتار+کلمات) → select (کاندیداها) → reframe (دنبال‌کردن سوژه) → subtitle → compose
(یک `filter_complex`) → export. هر مرحله پیشرفت را روی WebSocket گزارش می‌کند و **Stop**
در 0.2 ثانیه honored می‌شود (STATE §6).

## ۶) انضباط لایسنس (دروازه‌ی واقعی، نه شعار)

* لایسنس از **METADATA خودِ wheel** خوانده می‌شود، نه از README مخزن (`piper` روی PyPI
  GPL است در حالی که مخزنش MIT — دقیقاً موردی که این دروازه برای آن ساخته شد).
* GPL/AGPL/بدون‌لایسنس **هرگز** وارد مسیر نصب درون‌فرآیندی نمی‌شود؛ مجموعه‌ی REJECTED با
  دلیل در `engines.py` ثبت است (YOLOv8=AGPL، madmom=CC-BY-NC، Essentia=AGPL، …).
* موتورهای سنگین (torch و…) فقط on-demand و با رضایت کاربر؛ نبودِ هر موتور = افتادگی
  نرمال، نه خرابی.
* افزونه‌ها **برون‌فرآیندی**اند تا کد GPL هم قابل استفاده باشد بدون آن‌که لایسنس برنامه
  آلوده شود (`PROVIDERS.md`).
