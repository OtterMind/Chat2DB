# Style Match — توضیح کامل، از صفر

این متن برای کسی نوشته شده که هیچ‌چیز درباره‌ی برنامه نمی‌داند. اول با زبان ساده،
بعد با جزئیات فنی. اگر فقط می‌خواهی بدانی «این دکمه چه کار می‌کند»، خواندن بخش اول
کافی است.

---

## ۱. مسئله چیست

یک ویدیوی خوب در اینستاگرام می‌بینی و حس می‌کنی «کاش مال من هم این‌طوری بود».
چیزی که آن ویدیو را خوب کرده، معمولاً خودِ فیلم نیست — **شیوه‌ی تدوینش** است:

- نماها چقدر کوتاه‌اند و کِی عوض می‌شوند
- برش‌ها روی ضرب موسیقی می‌افتند یا نه
- دوربین ثابت است یا آرام به سوژه نزدیک می‌شود
- رنگ گرم است یا سرد، پرمایه است یا مات
- زیرنویس کجا می‌نشیند و چند کلمه در هر لحظه نشان داده می‌شود
- موسیقی زیر صدای گوینده چقدر پایین می‌آید

همه‌ی این‌ها **قابل اندازه‌گیری** هستند. `Style Match` دقیقاً همین کار را می‌کند:
ویدیوی الگو را اندازه می‌گیرد، از آن یک «دستور پخت» می‌سازد، و بعد **فیلم خودت** را
با همان دستور پخت می‌چیند.

## ۲. چه کاری نمی‌کند (مهم)

- **کپی نمی‌کند.** هیچ فریمی، هیچ آهنگی، هیچ فونتی از ویدیوی الگو برداشته نمی‌شود.
  چیزی که ذخیره می‌شود فقط عدد است: طول نماها، تمپو، درصد حرکت دوربین، رنگ.
- **گرافیک دست‌ساز را بازنمی‌سازد.** اگر آن ویدیو یک تیتراژ متحرک دست‌ساز دارد، ما
  می‌توانیم بگوییم «یک زیرنویس جعبه‌ای بالای کادر برای ۱٫۲ ثانیه بود»، ولی نمی‌توانیم
  همان انیمیشن را بسازیم.
- **آهنگ همان ویدیو را نمی‌آورد.** تمپو و رفتار موسیقی زیر صدا منتقل می‌شود، خود آهنگ نه.
- **«یک کلیک، همان ویدیو» نیست.** دستور زبان تدوین منتقل می‌شود؛ اجرا، متن و لوکیشن نه.

## ۳. از دید کاربر، سه قدم

1. **ویدیوی الگو را بده.** برنامه چند ثانیه فکر می‌کند و یک قالب می‌سازد و ذخیره می‌کند.
2. **قالب را ببین.** روی صفحه نوشته می‌شود: چند نما، میانه‌ی طول نما، چند ضرب در دقیقه،
   چند درصد برش‌ها روی ضرب، نسبت تصویر، ترکیب حرکت دوربین، نوع ترنزیشن — و فهرست
   چیزهایی که «قابل اندازه‌گیری نبود».
3. **فیلم خودت را بده.** برنامه هایلایت‌های فیلم تو را پیدا می‌کند، آن‌ها را روی ریتم قالب
   می‌چیند، رنگ و زوم و ترنزیشن و نسبت تصویر را اعمال می‌کند، زیرنویس می‌سازد (اگر مدل
   گفتار نصب باشد) و موسیقی را زیر صدا پایین می‌آورد (اگر آهنگ داده باشی) — و نتیجه
   در میز تدوین باز می‌شود، آماده‌ی خروجی گرفتن یا دستکاری بیشتر.

دکمه‌ی بزرگ صفحه یعنی همین: **همه‌کار را خودکار انجام بده.** نه پرامپتی، نه تنظیماتی.

## ۴. زیر پوسته: از چه ساخته شده

### موتورها

| موتور | نقش | پروانه |
|---|---|---|
| **FFmpeg** | رمزگشایی ویدیو و صدا، استخراج فریم، و ساخت خروجی نهایی | همراه برنامه |
| **NumPy** | همه‌ی ریاضیات: پوشش صدا، شار طیفی، خودهمبستگی، همبستگی فریم | BSD |
| **PySceneDetect** | پیدا کردن مرز نماها | BSD-3 |
| **OpenCV** (اختیاری) | فاز-همبستگی و تبدیل لگاریتمی-قطبی برای تشخیص زوم و پن | Apache-2.0 |
| **faster-whisper** (اختیاری) | رونویسی گفتار برای زیرنویس خودکار | MIT |
| تشخیص‌گر ضرب | نوشته‌ی خودمان، بدون وابستگی جدید | — |

هیچ سرویس ابری‌ای در کار نیست. همه‌چیز روی همان کامپیوتر اجرا می‌شود.

### فایل‌ها

```
ce-app/backend/core/engine/style.py      مغز تحلیل و برنامه‌ریزی
ce-app/backend/core/engine/audio.py      پوشش صدا، ضرب، منحنی داکینگ
ce-app/backend/core/engine/analyze.py    مرز نماها و سکوت‌ها
ce-app/backend/app/routers/style.py      چهار مسیر API
ce-app/frontend/src/pages/StyleMatch.tsx صفحه‌ای که کاربر می‌بیند
ce-app/backend/tests/test_style.py       ۱۳ تست با جواب‌های از پیش معلوم
```

### هر عدد چطور اندازه گرفته می‌شود

| چیزی که اندازه می‌گیریم | روش |
|---|---|
| مرز نماها | `scenedetect`، با جایگزین FFmpeg اگر نصب نبود |
| طول نماها | تفاضل مرزها؛ **میانه** گزارش می‌شود نه میانگین، چون یک نمای طولانی میانگین را خراب می‌کند |
| تمپو (BPM) | شار طیفی صدا → خودهمبستگی → اصلاح اکتاو (وگرنه ۱۵۰ به‌جای ۷۵ خوانده می‌شود) |
| برش روی ضرب | چند درصد برش‌ها در فاصله‌ی ۱۲۰ میلی‌ثانیه‌ی یک ضرب هستند |
| حرکت دوربین | چند فریم کوچک ۹۶×۹۶ از هر نما؛ اول جابه‌جایی با فاز-همبستگی حذف می‌شود، بعد مقیاس در فضای لگاریتمی-قطبی اندازه گرفته می‌شود → `static / pan / push / pull / handheld` |
| رنگ | نمونه‌گیری چند فریم → روشنایی، کنتراست، اشباع، اختلاف قرمز و آبی → همان اعدادی که اسلایدرهای تنظیم رنگ می‌گیرند |
| نسبت تصویر | از ابعاد واقعی فایل |
| گفتار | تشخیص سکوت FFmpeg → چند درصد ویدیو حرف زده می‌شود |
| نوع ترنزیشن | پروفایل اختلاف فریم دو طرف هر برش: پرش ناگهانی = برش سخت، تغییر تدریجی = محو |

### قالب چه شکلی است

یک فایل JSON کوچک با پسوند `.cetemplate` که در پوشه‌ی خانگی برنامه ذخیره می‌شود.
نمونه‌ی واقعی، از یک ویدیوی آزمایشی که خودمان با دستور مشخص ساختیم (هشت نمای ۱٫۵
ثانیه‌ای روی ضرب ۱۲۰):

```json
{
  "name": "demo",
  "duration": 12.0,
  "aspect": "9:16",
  "shots": [{ "start": 0.0, "duration": 1.52, "motion": "static", "energy": 0.017 }, "…"],
  "bpm": 120.19,
  "cuts_on_beat": 0.571,
  "median_shot": 1.52,
  "motion_mix": { "static": 0.875, "pan": 0.125, "push": 0.0, "pull": 0.0, "handheld": 0.0 },
  "look": { "brightness": -0.04, "contrast": 1.032, "saturation": 1.438, "temperature": -0.071 },
  "speech_ratio": 0.434,
  "captions": { "wanted": true, "position": "bottom", "style": "outline" },
  "unknown": ["on-screen graphics and hand-made titles", "…"]
}
```

آن کلید آخر عمدی است: **قالب خودش می‌گوید چه چیزهایی را نتوانسته بفهمد.**

### وقتی فیلم خودت را می‌دهی چه اتفاقی می‌افتد

1. **هایلایت‌ها**: اگر صدا دارد، بخش‌های حرف‌زدن با تشخیص سکوت پیدا و بر اساس طول
   رتبه‌بندی می‌شوند. اگر صدا ندارد، نماها بر اساس میزان حرکت تصویر رتبه می‌گیرند.
2. **چیدن**: به‌ازای هر نمای قالب، یک تکه از فیلم تو برداشته می‌شود، به همان طول
   (کوتاه‌تر اگر مصالح کم بیاورد). تکه‌ها **بدون فاصله** پشت هم می‌نشینند.
3. **حرکت دوربین**: اگر قالب گفته این نما زوم دارد، روی کلیپ تو **کی‌فریم** ساخته می‌شود
   — همان کی‌فریم‌هایی که در ادیتور قابل دیدن و ویرایش‌اند.
4. **رنگ**: اعداد قالب مستقیم روی تنظیمات رنگ هر کلیپ می‌نشیند.
5. **ترنزیشن**: اگر قالب محو داشته، بین کلیپ‌ها محو گذاشته می‌شود.
6. **زیرنویس**: اگر مدل گفتار در دسترس باشد، فیلم تو رونویسی و زیرنویس‌ها با سبک قالب
   روی لایه‌ی متن گذاشته می‌شود.
7. **موسیقی**: اگر آهنگ داده باشی، روی لایه‌ی صدا می‌نشیند و اگر قالب گفته موسیقی زیر
   صدا پایین می‌آید، منحنی داکینگ محاسبه و اعمال می‌شود.
8. **گزارش صادقانه**: در پایان دو فهرست نشان داده می‌شود — «انجام شد» و «انجام نشد».

### چهار مسیر API

```
POST /api/style/analyze          ویدیوی الگو → قالب (و ذخیره‌اش)
GET  /api/style/templates        فهرست قالب‌های ذخیره‌شده
POST /api/style/apply            قالب + فیلم تو (+ آهنگ) → تایم‌لاین آماده
DEL  /api/style/templates/{name} حذف یک قالب
```

خروجی `apply` دقیقاً همان ساختاری است که میز تدوین ذخیره می‌کند و موتور رندر
می‌سازد — یعنی چیزی که در ادیتور می‌بینی، همان چیزی است که خروجی می‌گیری.

## ۵. چطور مطمئنیم کار می‌کند

هر آزمایش با یک ویدیوی **ساختگی با جواب معلوم** انجام می‌شود:

- هشت نمای دقیقاً ۱٫۵ ثانیه‌ای → تحلیل‌گر میانه‌ی `1.52` می‌دهد
- ضرب دقیقاً ۱۲۰ → تحلیل‌گر `120.19` می‌دهد
- کلیپ‌هایی که با فرمول زوم و پن ساخته شده‌اند → `push`، `pull`، `pan`، `static` درست تشخیص داده می‌شوند
- تایم‌لاین ساخته‌شده: به‌ازای هر نمای قالب یک کلیپ، بدون فاصله، با رنگ اعمال‌شده
- و در پایان، همان تایم‌لاین با موتور عادی رندر می‌شود تا مطمئن شویم واقعاً قابل خروجی گرفتن است

## ۶. محدودیت‌های امروز

- تایپوگرافی دقیق زیرنویس الگو (فونت، اندازه، رنگ) هنوز خوانده نمی‌شود؛ سبک پیش‌فرض تمیز استفاده می‌شود.
- تشخیص «زوم اوت» ضعیف‌تر از بقیه است.
- انتخاب هایلایت بر اساس گفتار و انرژی تصویر است، نه فهم محتوا. مرحله‌ی بعدی همین است:
  یک مدل زبانی محلی که از روی متن گفتار تصمیم بگیرد کدام لحظه‌ها قصه می‌سازند.
- فیس‌ترکینگ هنوز برش از مرکز است.
